# Engineering change report — NS-B___

**Ticket / branch / commit:**

**Observed defect:** Include exact input, expected response, observed response, and reproduction command.

**Root cause and trust boundary:** Explain which component owned the failed invariant.

**Design alternatives considered:** Compare at least two options and why you chose the submitted change.

**Test evidence:** Paste commands and summarized results, including a negative test and affected neighboring behavior.

**Deployment and migration risk:** Document schema compatibility, concurrency, security implications and rollback constraints.

**Review request:** Ask a teammate to inspect one specific risk; do not claim a simulated review independently verified code.

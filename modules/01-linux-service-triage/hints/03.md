# Hints — Unit 3

**Hint 1 (concept).** The basic check passes, so the problem only shows up *under load*.
Read exactly what `--stress` prints when it fails — it names what it's unhappy about.
Then ask: where does that value come from? Config isn't only one file.

**Hint 2 (tactic).** `telemetryd` loads `etc/telemetryd.conf` first, then applies every
override in `etc/telemetryd.d/`. An override can quietly replace a safe value with an
unsafe one. Compare what the base config says to what the agent actually reports it's
using.

```bash
bash bin/telemetryd --stress          # read the E_LOAD line
grep -r max_batch etc/                 # where is this set, and to what?
```

**Hint 3 (the cause).** `etc/telemetryd.d/90-local.conf` overrides `max_batch` to
`100000`, far above the safe limit of 500 — it was added during a past incident and never
reverted. The network theory was a red herring. Remove the override (or correct its value
to ≤ 500), re-run `--stress`, and write up what you found.
